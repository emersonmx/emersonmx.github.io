Http Proxy with Rust

2026-09-23 17:24:07

This post is about building an HTTP proxy with Rust.

The base version came from commit 800f6988, and the first working code is in src/main.rs.

This first version used tokio and hyper. At this stage, the proxy could:

  1. Listen on 127.0.0.1:8888
  2. Accept incoming HTTP/1.1 connections
  3. Converted request body to boxed body (buffered)
  4. Opened outbound TCP connection to target host
  5. Rebuilt the Host header based on destination
  6. Forwarded request and returned response to the client

The request lifecycle looked like this:

client
  -> proxy (127.0.0.1:8888)
  -> parse target
  -> open tcp connection
  -> send request
  -> receive response
  -> client

Inside fetch, the proxy extracted target address from:

  • request URI host/port when available
  • fallback to Host header (with default ports 80/443)

After resolving the address, it removed any previous Host header and inserted one that matched the outbound destination.

This detail matters because origin servers can reject or misroute requests when Host does not match the expected virtual host.

In many proxy implementations, streaming is preferred to reduce memory usage and latency. In this case, buffering is intentional because inspection requires access to request and response payloads.

To inspect payloads, apply rules, or store traces, the proxy needs a buffered representation of the body. Because of that, this version uses collect() on purpose.

This first version was intentionally minimal, but already good enough to:

  • test real browser/client traffic for plain HTTP
  • validate Hyper client/server handshake model
  • expose edge cases before adding HTTPS tunneling (CONNECT)

In other words, it was a practical starting point before tackling the harder HTTPS side.
